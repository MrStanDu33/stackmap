# 3. Kysely with SQLite by default and Postgres optional

- Status: accepted
- Date: 2026-10-10

## Context

Most self-hosters want one container and one volume. A cloud offer, and larger installations, need Postgres. Better
Auth, which handles accounts and workspaces, supports Kysely natively.

## Decision

- Use **Kysely** for queries and migrations, with one dialect-agnostic code path. `DATABASE_URL` selects the dialect:
  empty or a file path for SQLite (`better-sqlite3`), a `postgres://` URL for Postgres (`pg`).
- **SQLite is the default**, stored in the `/data` volume.
- A serialize helper owns the dialect differences: JSON columns, timestamps as ISO-8601 UTC text, booleans.
- IDs are UUIDv7 text generated by the app.
- Search uses a `search_index` table with a normalized column (lowercase, accents removed) and escaped `LIKE`
  patterns, so it behaves the same on both databases.
- Migrations run at startup. SQLite cannot change a column type or constraint, so a helper rebuilds tables when needed.
- Better Auth's schema is generated into our migrations, so there is one migration history.

## Consequences

- Integration tests and migration tests run on both databases in CI.
- No database-specific features (Postgres full-text search, JSONB operators) unless both dialects get an equivalent.
